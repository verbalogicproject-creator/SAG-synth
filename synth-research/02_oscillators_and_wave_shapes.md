# 02 — Oscillators and Wave Shapes

## Native Web Audio Oscillator Types
The native `OscillatorNode` supports four built-in wave shapes plus a custom mode:
- `sine`
- `square`
- `sawtooth`
- `triangle`
- `custom` (requires a `PeriodicWave`) [web:45]

```js
const osc = new OscillatorNode(audioCtx, { type: "sine", frequency: 440 });
osc.connect(audioCtx.destination);
osc.start();
```

## Tone.js Oscillator Types
Tone.js's `Tone.Synth` / `Tone.MonoSynth` accept an `oscillator.type` option with the same four base shapes, plus richer variants:
- `sine`, `square`, `sawtooth`, `triangle`
- Partial-count variants like `sine4`, `square8` (limits harmonic partials — useful for anti-aliasing at high frequencies) [web:18]
- `fatsawtooth`, `fatsquare` (detuned unison stacks — several oscillators slightly detuned for a "fat" analog sound)
- `pwm` (pulse-width modulation oscillator, via `Tone.PWMOscillator`)
- `pulse` (`Tone.PulseOscillator`, adjustable width)
- FM/AM synthesis engines: `Tone.FMSynth`, `Tone.AMSynth` combine two oscillators (carrier + modulator) for more complex timbres [web:46][web:51]

```js
const synth = new Tone.Synth({
  oscillator: { type: "fatsawtooth", count: 3, spread: 20 }
}).toDestination();
```

## Custom Wavetables / Wave Shapes (PeriodicWave)
For genuinely custom waveforms (not just the four presets), use `PeriodicWave`, defined by Fourier coefficients (`real`/`imag` arrays):

```js
const wave = new PeriodicWave(audioCtx, {
  real: wavetable.real,
  imag: wavetable.imag,
});
const osc = new OscillatorNode(audioCtx, {
  frequency: 380,
  type: "custom",
  periodicWave: wave,
});
```

To turn an arbitrary time-domain waveform (e.g., a hand-drawn or sampled cycle) into harmonic coefficients for `PeriodicWave`, run an FFT over one period of the waveform: the magnitude of each FFT bin becomes a harmonic power level (real/imag pair) [web:58]. Chrome Labs / MDN maintain a repository of pre-computed wavetables that can be dropped in directly as `real`/`imag` arrays [web:45].

Practical approach for a "wavetable synth" feature:
1. Store multiple single-cycle waveforms (as arrays of samples) representing different timbres.
2. FFT each cycle once, cache the `real`/`imag` coefficient arrays.
3. Let the user morph/select between wavetable "frames" by swapping the oscillator's `PeriodicWave` or cross-fading two oscillators tuned to adjacent frames.
4. For real-time wavetable scanning/morphing beyond what `PeriodicWave` swaps allow smoothly, implement this inside an `AudioWorkletProcessor` reading directly from a Float32Array wavetable buffer per sample — this gives sample-accurate control unavailable via discrete `PeriodicWave` swaps.

## AudioWorklet for Custom DSP Oscillators
When you need algorithms Tone.js/native oscillators don't offer (granular synthesis, wavetable interpolation, custom noise coloring, physical modeling), write an `AudioWorkletProcessor`:

```js
// worklet file: my-oscillator-processor.js
class MyOscillatorProcessor extends AudioWorkletProcessor {
  static get parameterDescriptors() {
    return [{ name: 'frequency', defaultValue: 440, minValue: 20, maxValue: 20000 }];
  }
  constructor() {
    super();
    this.phase = 0;
  }
  process(inputs, outputs, parameters) {
    const output = outputs[0];
    const freq = parameters.frequency;
    for (let channel = 0; channel < output.length; channel++) {
      const outputChannel = output[channel];
      for (let i = 0; i < outputChannel.length; i++) {
        const f = freq.length > 1 ? freq[i] : freq[0];
        outputChannel[i] = Math.sin(this.phase);
        this.phase += (2 * Math.PI * f) / sampleRate;
      }
    }
    return true;
  }
}
registerProcessor('my-oscillator-processor', MyOscillatorProcessor);
```

```js
// main thread
await audioCtx.audioWorklet.addModule('my-oscillator-processor.js');
const node = new AudioWorkletNode(audioCtx, 'my-oscillator-processor');
node.connect(audioCtx.destination);
```

AudioWorklet runs on the audio rendering thread (not main thread), avoiding glitches from JS garbage collection/UI work — essential for anything beyond simple oscillators [web:45].

## Noise Generator
White/pink/brown noise is a standard "wave shape" option in most synths, generated by filling an `AudioBuffer` with random samples, or via `Tone.Noise`:

```js
const noise = new Tone.Noise("pink").start();
```

Manually:
```js
const bufferSize = audioCtx.sampleRate * duration;
const noiseBuffer = new AudioBuffer({ length: bufferSize, sampleRate: audioCtx.sampleRate });
const data = noiseBuffer.getChannelData(0);
for (let i = 0; i < bufferSize; i++) data[i] = Math.random() * 2 - 1;
```
Noise colors differ by spectral rolloff: white (flat), pink (-3dB/octave), brown (-6dB/octave) [web:6].

## Unison / Detune Stacking
A "fat" analog feel comes from stacking multiple detuned copies of an oscillator (unison). Tone.js exposes this natively via `fatsawtooth`/`fatsquare` with `count` (voices) and `spread` (cents detune). If building manually, spawn N oscillators per note, detune each by an evenly-spaced spread (e.g. -20, 0, +20 cents), and sum through a shared gain stage.

## Wave Shape UI Recommendations
Expose at minimum: Sine, Triangle, Sawtooth, Square/Pulse (with width knob), Noise (white/pink/brown), plus an optional Wavetable/Custom mode. Show a live oscilloscope (via `AnalyserNode.getFloatTimeDomainData`) so users can see the waveform they're selecting — critical for a "decent" synth UX.
